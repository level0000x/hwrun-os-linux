HWRun OS STORAGE 实现文档

模块名称： STORAGE (Storage Backend Protocol)
版本： 1.0.0
状态： 设计冻结
定位： 存储后端协议，提供存储卷管理、快照、备份、精简配置等存储功能的统一抽象
实现语言： C（内核模块 + 用户态辅助服务）
依赖： 微内核（任务、IPC、内存）、METAPROTO（协议注册）、PARAM（参数读取）、LOG（日志记录）、FSP（文件系统协议）、HAP（硬件抽象）
提供协议： STORAGE

一、设计哲学

1.1 核心定位

STORAGE 是 HWRun OS 的存储管理核心——所有与存储卷、快照、备份、精简配置、存储池相关的操作都通过 STORAGE 协议进行。

```
STORAGE = 存储后端协议 = 所有存储操作的统一入口

上层插件 (INSTANCE, CONTAINER, PKGMGR, FSP, CLUSTER, ...)
    │
    │  通过 STORAGE 协议管理存储
    ▼
STORAGE 插件 (内核模块 + 用户态服务)
    │
    │  基于 Linux 存储栈
    │  ├── Device Mapper (dm)        → 卷管理、快照、加密
    │  ├── LVM (逻辑卷管理)           → 卷组、逻辑卷、精简池
    │  ├── 块设备层 (Block Layer)    → 设备发现、分区管理
    │  ├── SCSI 子系统              → SCSI 设备管理
    │  ├── NVMe 驱动                → NVMe 设备管理
    │  └── 文件系统层 (FSP)          → 格式化、挂载
    │
    ▼
Linux 内核 (Device Mapper / LVM / Block / SCSI / NVMe)
```

1.2 设计原则

1. 协议驱动：所有存储操作通过 STORAGE 协议进行
2. 分层抽象：存储设备 → 存储池 → 存储卷 → 快照 → 备份
3. 精简配置：支持 thin provisioning，按需分配存储空间
4. 快照与回滚：支持存储卷的即时快照和回滚
5. 多后端支持：支持本地存储、网络存储（iSCSI、NVMe-oF）、分布式存储
6. 热插拔：支持存储设备的在线添加和移除

1.5 STORAGE 插件的本质

STORAGE 插件 = Linux Device Mapper + LVM + 块设备层的 HWRun 协议封装

Device Mapper 是 Linux 内核提供的框架，用于将物理块设备映射到更高级的虚拟块设备。它构成了逻辑卷管理器（LVM）、软件 RAID、dm-crypt 磁盘加密的基础。

2.2 STORAGE 在 HWRun OS 中的位置

```
系统启动顺序：
BIOS/UEFI → 引导加载器 → 微内核 → METAPROTO → BUS → PARAM → LOG → GIT → HAP → PMP → FSP → NP → SP → LOADER → CLUSTER → INSTANCE → SANDBOX → INPUT → DISPLAY → PERMISSION → STORAGE → 其他插件
                                                                                                                               ↑
                                                                                                                     STORAGE 在这里加载
```

STORAGE 插件在 PERMISSION 之后、上层应用插件之前加载，为系统提供存储管理能力。

2.3 STORAGE 的上层消费者

上层插件 需要 STORAGE 提供什么
INSTANCE (实例管理) 实例根文件系统存储卷
CONTAINER (容器) 容器存储卷
PKGMGR (包管理) 包缓存存储
CLUSTER (集群) 分布式存储卷
FSP (文件系统) 存储设备挂载

三、核心数据结构

```c
// storage/include/storage.h

#include <stdint.h>
#include <stddef.h>
#include <time.h>

/* ============================================================
   存储设备类型
   ============================================================ */
typedef enum {
    STORAGE_DEVICE_UNKNOWN = 0,
    STORAGE_DEVICE_NVME,            // NVMe SSD
    STORAGE_DEVICE_SATA,            // SATA SSD/HDD
    STORAGE_DEVICE_SAS,             // SAS HDD/SSD
    STORAGE_DEVICE_SCSI,            // SCSI 设备
    STORAGE_DEVICE_ISCSI,           // iSCSI 设备
    STORAGE_DEVICE_NVME_OF,         // NVMe-oF 设备
    STORAGE_DEVICE_VIRTIO,          // VirtIO 块设备
    STORAGE_DEVICE_LOOP,            // Loop 设备
    STORAGE_DEVICE_DM,              // Device Mapper 设备
    STORAGE_DEVICE_LVM,             // LVM 逻辑卷
} storage_device_type_t;

/* ============================================================
   存储池类型
   ============================================================ */
typedef enum {
    STORAGE_POOL_LINEAR = 0,        // 线性聚合
    STORAGE_POOL_STRIPED,           // 条带 (RAID 0)
    STORAGE_POOL_MIRROR,            // 镜像 (RAID 1)
    STORAGE_POOL_RAID5,             // RAID 5
    STORAGE_POOL_RAID6,             // RAID 6
    STORAGE_POOL_RAID10,            // RAID 10
    STORAGE_POOL_THIN,              // 精简池
} storage_pool_type_t;

/* ============================================================
   存储卷信息
   ============================================================ */
typedef struct storage_volume {
    char id[64];                    // 卷 ID (UUID)
    char name[128];                 // 卷名称
    uint64_t size;                  // 总大小 (字节)
    uint64_t used;                  // 已使用 (字节)
    uint64_t available;             // 可用 (字节)
    char path[256];                 // 设备路径 (如 /dev/mapper/vol-xxx)
    char mount_point[256];          // 挂载点
    char fstype[32];                // 文件系统类型 (ext4, xfs, btrfs)
    int mounted;                    // 是否已挂载
    int readonly;                   // 是否只读
    uint64_t created_at;            // 创建时间
    uint64_t modified_at;           // 修改时间
    char pool_id[64];               // 所属存储池 ID
    char snapshot_of[64];           // 快照源卷 ID
    struct storage_volume *next;
} storage_volume_t;

/* ============================================================
   存储池信息
   ============================================================ */
typedef struct storage_pool {
    char id[64];                    // 池 ID
    char name[128];                 // 池名称
    storage_pool_type_t type;       // 池类型
    uint64_t total_size;            // 总大小 (字节)
    uint64_t used_size;             // 已使用 (字节)
    uint64_t available_size;        // 可用 (字节)
    uint32_t device_count;          // 物理设备数量
    char **devices;                 // 设备路径列表
    int thin_provisioning;          // 是否启用精简配置[reference:3]
    uint64_t thin_pool_metadata;    // 精简池元数据大小
    struct storage_pool *next;
} storage_pool_t;

/* ============================================================
   快照信息
   ============================================================ */
typedef struct storage_snapshot {
    char id[64];                    // 快照 ID
    char name[128];                 // 快照名称
    char volume_id[64];             // 源卷 ID
    uint64_t size;                  // 快照大小
    uint64_t created_at;            // 创建时间
    int active;                     // 是否活跃
    struct storage_snapshot *next;
} storage_snapshot_t;

/* ============================================================
   备份信息
   ============================================================ */
typedef struct storage_backup {
    char id[64];                    // 备份 ID
    char name[128];                 // 备份名称
    char volume_id[64];             // 源卷 ID
    char location[256];             // 备份位置 (文件路径)
    uint64_t size;                  // 备份大小
    uint64_t created_at;            // 创建时间
    int compressed;                 // 是否压缩
    int encrypted;                  // 是否加密
    struct storage_backup *next;
} storage_backup_t;

/* ============================================================
   STORAGE 上下文
   ============================================================ */
typedef struct storage_context {
    int initialized;
    uint64_t storage_task_id;       // STORAGE 自身的任务 ID
    
    storage_pool_t *pools;          // 存储池列表
    storage_volume_t *volumes;      // 存储卷列表
    storage_snapshot_t *snapshots;  // 快照列表
    storage_backup_t *backups;      // 备份列表
    
    void *lock;
} storage_context_t;
```

5.3 Device Mapper 操作

Device Mapper 是 Linux 内核中用于创建虚拟块设备的框架。它通过 ioctl 系统调用与用户空间交互，用户界面是 dmsetup 命令。

```c
// storage/src/storage_dm.c

#include <linux/kernel.h>
#include <linux/slab.h>
#include <linux/string.h>
#include <linux/device-mapper.h>
#include <linux/dm-ioctl.h>
#include <linux/dm-linear.h>
#include <linux/dm-snapshot.h>
#include <linux/dm-thin.h>

#include "storage.h"
#include "storage_dm.h"

/* ============================================================
   创建 Device Mapper 线性设备
   ============================================================ */
int storage_dm_create_linear(const char *dm_name, const char *source_dev,
                              uint64_t offset) {
    struct dm_ioctl *dmi;
    struct dm_target_spec *spec;
    char *params;
    int fd;
    int ret;
    
    // 1. 打开 /dev/mapper/control
    fd = open("/dev/mapper/control", O_RDWR);
    if (fd < 0) {
        return -1;
    }
    
    // 2. 分配 DM ioctl 结构
    dmi = kmalloc(sizeof(struct dm_ioctl) + 512, GFP_KERNEL);
    if (!dmi) {
        close(fd);
        return -ENOMEM;
    }
    
    memset(dmi, 0, sizeof(struct dm_ioctl) + 512);
    strncpy(dmi->name, dm_name, DM_NAME_LEN - 1);
    dmi->version[0] = DM_VERSION_MAJOR;
    dmi->version[1] = DM_VERSION_MINOR;
    dmi->version[2] = DM_VERSION_PATCHLEVEL;
    dmi->data_size = sizeof(struct dm_ioctl) + 512;
    dmi->data_start = sizeof(struct dm_ioctl);
    dmi->target_count = 1;
    
    // 3. 设置目标
    spec = (struct dm_target_spec *)((char *)dmi + dmi->data_start);
    spec->sector_start = 0;
    spec->length = 1024 * 1024;  // 1GB
    strncpy(spec->target_type, "linear", DM_TARGET_NAME_LEN - 1);
    spec->next = sizeof(struct dm_target_spec);
    
    // 4. 参数: 设备 偏移
    params = (char *)spec + spec->next;
    snprintf(params, 256, "%s %llu", source_dev, offset);
    
    // 5. 创建设备
    ret = ioctl(fd, DM_DEV_CREATE, dmi);
    if (ret < 0) {
        close(fd);
        kfree(dmi);
        return ret;
    }
    
    // 6. 加载表
    ret = ioctl(fd, DM_TABLE_LOAD, dmi);
    
    // 7. 挂载设备
    ret = ioctl(fd, DM_DEV_SUSPEND, dmi);
    
    close(fd);
    kfree(dmi);
    return ret;
}
```

```c
int storage_create_volume(const char *name, const char *pool_id,
                           uint64_t size, const char *fstype,
                           int thin, char *out_id) {
    storage_pool_t *pool;
    storage_volume_t *vol;
    char device_path[256];
    int ret;
    
    // 1. 查找存储池
    pool = storage_find_pool(pool_id);
    if (!pool) {
        return -ENOENT;
    }
    
    // 2. 生成卷 ID
    storage_generate_id(out_id, 64);
    
    // 3. 根据池类型创建卷
    if (pool->type == STORAGE_POOL_LVM || pool->type == STORAGE_POOL_THIN) {
        // 使用 LVM 创建逻辑卷
        ret = storage_lvm_create_lv(pool->name, name, size / (1024 * 1024), thin);
        if (ret < 0) {
            return ret;
        }
        snprintf(device_path, sizeof(device_path), "/dev/%s/%s", pool->name, name);
    } else if (pool->type == STORAGE_POOL_LINEAR) {
        // 使用 Device Mapper 线性映射
        if (pool->device_count < 1) {
            return -ENODEV;
        }
        ret = storage_dm_create_linear(name, pool->devices[0], 0);
        if (ret < 0) {
            return ret;
        }
        snprintf(device_path, sizeof(device_path), "/dev/mapper/%s", name);
    } else {
        return -ENOTSUP;
    }
    
    // 4. 创建文件系统 (mkfs)
    if (fstype && fstype[0] != '\0') {
        storage_mkfs(device_path, fstype);
    }
    
    // 5. 创建卷记录
    vol = kmalloc(sizeof(storage_volume_t), GFP_KERNEL);
    if (!vol) {
        return -ENOMEM;
    }
    
    memset(vol, 0, sizeof(storage_volume_t));
    strncpy(vol->id, out_id, sizeof(vol->id) - 1);
    strncpy(vol->name, name, sizeof(vol->name) - 1);
    vol->size = size;
    vol->created_at = get_jiffies_64();
    strncpy(vol->path, device_path, sizeof(vol->path) - 1);
    if (fstype) {
        strncpy(vol->fstype, fstype, sizeof(vol->fstype) - 1);
    }
    strncpy(vol->pool_id, pool_id, sizeof(vol->pool_id) - 1);
    vol->mounted = 0;
    
    // 6. 添加到列表
    vol->next = g_storage_ctx.volumes;
    g_storage_ctx.volumes = vol;
    
    return 0;
}

   删除存储卷

int storage_delete_volume(const char *volume_id, int force) {

    if (vol->mounted) {
        storage_umount_volume(volume_id);
    }
    
    // 2. 根据卷类型删除
    // LVM: lvremove
    // DM: dmsetup remove
    
    // 3. 从列表中移除
    storage_remove_volume(vol);
    
    return 0;
```

5.6 IPC 消息处理

```c
// storage/src/storage_ipc.c

#include <linux/slab.h>
#include <linux/uaccess.h>

#include "storage.h"
#include "storage_ipc.h"
#include "storage_volume.h"
#include "storage_pool.h"
#include "storage_snapshot.h"
#include "storage_backup.h"

/* ============================================================
   IPC 消息处理入口
   ============================================================ */
void storage_ipc_handler(uint64_t from_task, void *data, size_t len) {
    uint32_t msg_type = *(uint32_t *)data;
    
    switch (msg_type) {
        case STORAGE_MSG_CREATE_VOLUME: {
            storage_create_volume_req_t *req =
                (storage_create_volume_req_t *)data;
            storage_create_volume_resp_t resp;
            int ret = storage_create_volume(req->name, req->pool_id,
                                             req->size, req->fstype,
                                             req->thin, resp.volume_id);
            resp.success = (ret == 0);
            resp.error = ret;
            ipc_reply(from_task, &resp, sizeof(resp));
            break;
        }
        
        case STORAGE_MSG_DELETE_VOLUME: {
            char *volume_id = (char *)data;
            int ret = storage_delete_volume(volume_id, 0);
            ipc_reply(from_task, &ret, sizeof(ret));
            break;
        }
        
        case STORAGE_MSG_LIST_VOLUMES: {
            storage_list_volumes_req_t *req =
                (storage_list_volumes_req_t *)data;
            storage_volume_t *volumes;
            uint32_t count;
            storage_get_volumes(&volumes, &count, req->pool_id);
            ipc_reply(from_task, volumes, count * sizeof(storage_volume_t));
            break;
        }
        
        case STORAGE_MSG_MOUNT_VOLUME: {
            storage_mount_volume_req_t *req =
                (storage_mount_volume_req_t *)data;
            int ret = storage_mount_volume(req->volume_id, req->mount_point,
                                            req->options);
            ipc_reply(from_task, &ret, sizeof(ret));
            break;
        }
        
        case STORAGE_MSG_SNAPSHOT: {
            storage_snapshot_req_t *req = (storage_snapshot_req_t *)data;
            storage_snapshot_resp_t resp;
            int ret = storage_snapshot_volume(req->volume_id, req->snapshot_name,
                                               resp.snapshot_id);
            resp.success = (ret == 0);
            resp.error = ret;
            ipc_reply(from_task, &resp, sizeof(resp));
            break;
        }
        
        default:
            printk(KERN_WARNING "HWRun STORAGE: Unknown IPC message type: %u\n",
                   msg_type);
            break;
    }
}
```

核心技术 Device Mapper、LVM、块设备层、SCSI 子系统
关键功能 存储池管理、存储卷管理、快照、备份、精简配置、设备发现

STORAGE 是 HWRun OS 中存储管理的核心插件。它基于 Linux 内核的 Device Mapper、LVM 和块设备层，通过 STORAGE 协议向上层插件提供存储池管理、存储卷管理、快照、备份、精简配置、设备发现等完整的存储管理功能。Device Mapper 是 Linux 内核提供的框架，用于将物理块设备映射到更高级的虚拟块设备，构成了 LVM、软件 RAID 和 dm-crypt 磁盘加密的基础。上层插件（INSTANCE、CONTAINER、PKGMGR、CLUSTER 等）通过 STORAGE 协议进行存储操作，不直接操作 Device Mapper、LVM 或块设备接口。
