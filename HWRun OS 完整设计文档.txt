一、项目定位

1.1 核心定义

HWRun OS 是一个操作系统插件容器。 它本身不实现任何具体功能，只提供微内核 + 组件总线 + 参数系统 + 协议定义 + Git 版本控制。所有功能——内核、libc、init、文件系统、网络、工具、应用格式——都是插件，用户按需安装、任意替换、随时卸载。所有行为由参数决定。软件没有专有格式，只有协议和插件。系统本身由 Git 管理，一切操作都是 Git 操作，历史自动管理。

"HWRun OS = 微内核 + 组件总线 + 参数系统 + Git。插件提供能力，参数决定行为，Git 管理一切。"

1.2 核心公式

```
HWRun OS = 微内核 + 组件总线 + 参数系统 + Git

微内核: 最小核心 (进程/内存/中断/插件加载器/协议路由)
组件总线: 插件管理器 (发现/加载/替换/生命周期/跨节点)
参数系统: 所有配置是参数 (参数驱动一切)
Git: 版本控制 (存储/同步/日志/版本/备份/认证)

插件 (What):
├── 提供能力
├── 实现协议
└── 可以被替换

参数 (How):
├── 决定用哪个插件
├── 决定插件怎么工作
├── 决定系统怎么运行
└── 可以被修改

Git (History):
├── 存储所有状态
├── 记录所有变更
├── 同步所有节点
├── 可回滚到任意状态
└── 历史自动管理

软件格式 (Plugin):
├── 没有专有格式
├── 只有 plugin.yml + 协议实现
├── 安装 = 安装插件
└── 运行 = 调用协议
```

1.3 关键特性

特性 说明
一切皆插件 从内核到 UI，所有功能都是可插拔插件
一切皆参数 所有配置、行为、选择都由参数决定
Git 原生 系统本身是 Git 仓库，所有操作是 Git 操作
历史自动管理 Git 历史自动合并压缩，tag 永久保留
协议驱动 插件间只通过标准化协议通信
内核可换 Linux 内核可以换成 FreeBSD 内核、自研内核
格式可换 可运行 ELF / PE / Mach-O / APK / EXE / DMG / WASM / JAR
分布式原生 整个集群就是一个操作系统
异构节点 集群内不同节点可运行不同插件组合
热插拔 运行时安装/卸载/替换插件
可撤销副作用 卸载插件时完全清理所有影响
无专有格式 软件格式就是插件格式

二、设计哲学

2.1 一切皆插件

```
传统系统: 固定功能，用户只能在外围加东西

HWRun OS: 所有功能都是插件，从内核到 UI 全部可换

插件层级:
├── 内核插件 (Linux / FreeBSD / 自研)
├── libc 插件 (glibc / musl / 自研)
├── init 插件 (systemd / openrc / runit / 自研)
├── 文件系统插件 (ext4 / btrfs / zfs / 自研)
├── 网络插件 (tcpip / zerotier / 自研)
├── 安全插件 (apparmor / selinux / 自研)
├── 存储插件 (local / ceph / 自研)
├── 日志插件 (journald / syslog-ng / 自研)
├── 工具插件 (coreutils / busybox / 自研)
├── 调度插件 (cfs / hwrun-sched / 自研)
├── 格式加载器插件 (ELF / PE / Mach-O / APK / EXE / DMG)
├── Git 插件 (storage / sync / log / version / auth / backup)
├── UI 插件 (cli / tui / gui / web)
└── 任意外部项目 → 直接封装成插件
```

2.2 一切皆参数

```
插件是 What 的抽象，参数是 How 的抽象。

插件 (What):
├── 提供能力
├── 实现协议
└── 可以被替换

参数 (How):
├── 决定用哪个插件
├── 决定插件怎么工作
├── 决定系统怎么运行
└── 可以被修改

参数驱动:
├── 系统启动: 读取参数 → 加载对应插件
├── 插件选择: 参数决定用哪个插件
├── 插件配置: 参数决定插件行为
├── 格式选择: 参数决定用哪个加载器
├── Git 操作: 参数决定同步策略/历史管理
└── 运行时: 参数改变时动态调整
```

2.3 Git 原生

```
系统本身是 Git 仓库:

/ = Git 仓库
├── .hwrun/          → Git 仓库
├── 插件 = 子模块
├── 配置 = 文件
├── 快照 = commit
├── 版本 = tag
├── 配置方案 = branch
└── 集群 = clone + sync

所有操作 = Git 操作:
├── 安装插件 = git submodule add
├── 更新插件 = git pull
├── 切换插件 = git checkout
├── 保存状态 = git commit
├── 回滚系统 = git reset
├── 集群同步 = git push/pull
└── 查看历史 = git log
```

2.4 协议驱动，实现无关

```
插件之间不直接调用，通过标准化协议通信

协议定义 (Protocol):
├── 不依赖具体实现
├── 版本管理
├── 向后兼容
└── 跨格式支持

插件 (Plugin):
├── 实现协议接口
├── 可独立替换
└── 替换时其他插件无感知
```

2.5 无专有格式

```
HWRun OS 的软件格式 = 插件格式

没有:
├── .hwrun
├── .hwpkg
├── .app
└── 任何专有格式

只有:
├── plugin.yml (描述)
├── 协议实现 (代码)
├── 参数配置 (行为)
└── Git 仓库 (存储)

第三方软件:
├── 提供 plugin.yml
├── 实现协议适配层
├── 原程序不变
└── 适配层桥接协议
```

2.6 可撤销副作用

```
安装插件时记录所有操作:
├── 复制文件 → 记录路径
├── 加载内核模块 → 记录模块名
├── 创建配置 → 记录路径
├── 启动服务 → 记录服务名
├── 挂载文件系统 → 记录挂载点
└── 修改系统状态 → 记录修改

卸载时逆向执行:
├── 停止服务
├── 卸载文件系统
├── 删除配置
├── 卸载内核模块
├── 删除文件
└── 系统回到安装前状态
```

2.7 插件来源

```
插件来源不限:
├── HWRun 官方仓库 (Git)
├── 第三方开发者 (Git)
├── 其他开源项目 (直接封装)
├── 商业软件 (封装后分发)
└── 用户自己写的
```

四、微内核

4.1 设计原则

```
微内核只包含:
├── 进程调度接口 (最小接口)
├── 内存管理接口 (最小接口)
├── 中断处理
├── 插件加载器
├── 组件总线接口
├── 参数系统接口
├── Git 接口
├── 最小 IPC
└── 协议路由表

微内核不包含:
├── 具体调度算法 (由调度插件提供)
├── 具体文件系统 (由文件系统插件提供)
├── 具体网络栈 (由网络插件提供)
├── 具体安全策略 (由安全插件提供)
├── 具体格式加载 (由加载器插件提供)
├── Git 具体操作 (由 Git 插件提供)
├── 用户管理 (由权限插件提供)
├── 集群管理 (由集群插件提供)
└── UI (由 UI 插件提供)
```

4.2 微内核接口

```c
/* microkernel/hwrun.h */

/* 进程调度接口 (由调度插件实现) */
struct hwrun_sched_ops {
    int (*init)(void);
    int (*submit)(struct task *t);
    int (*cancel)(uint64_t task_id);
    int (*yield)(void);
    int (*set_affinity)(pid_t pid, int *cpus, int n_cpus);
    int (*set_policy)(const char *policy);
    struct task_info *(*get_info)(uint64_t task_id);
};

/* 内存管理接口 (由内存插件实现) */
struct hwrun_mem_ops {
    void *(*alloc)(size_t size, enum hwrun_device_hint hint);
    void (*free)(void *ptr);
    int (*migrate)(void *ptr, size_t size, enum hwrun_device_hint target);
};

/* 参数接口 (由参数系统管理) */
struct hwrun_param {
    char *key;
    char *value;
    char *type;
    int (*set)(struct hwrun_param *self, const char *value);
    char *(*get)(struct hwrun_param *self);
};

/* Git 接口 (由 Git 插件实现) */
struct hwrun_git_ops {
    int (*init)(const char *path);
    int (*commit)(const char *message);
    int (*push)(void);
    int (*pull)(void);
    int (*clone)(const char *remote, const char *path);
    int (*tag)(const char *name);
    int (*checkout)(const char *ref);
    int (*reset)(const char *ref);
    int (*log)(char *output, size_t size);
    int (*blame)(const char *path, char *output, size_t size);
    int (*size)(uint64_t *size);
    int (*compact)(int level);
};

/* 插件接口 (由组件总线管理) */
struct hwrun_plugin {
    char *id;
    char *name;
    char *version;
    char *protocol;
    int (*init)(struct hwrun_plugin *self);
    int (*start)(struct hwrun_plugin *self);
    int (*stop)(struct hwrun_plugin *self);
    int (*destroy)(struct hwrun_plugin *self);
    void *(*get_interface)(const char *protocol);
    int (*configure)(struct hwrun_plugin *self, struct hwrun_param *params);
};

/* 协议路由 (由微内核管理) */
struct hwrun_protocol_route {
    char *name;
    char *version;
    char *plugin_id;
    void *implementation;
};
```

4.3 微内核大小

```
微内核目标:
├── 源码: ~5000 行 C
├── 编译后: ~200KB
├── 运行时内存: ~10MB
└── 不包含: 任何具体实现
```

五、组件总线

5.1 设计原则

```
组件总线 = 系统的"插件管理器"

功能:
├── 插件发现: 扫描 Git 仓库中的插件
├── 参数匹配: 根据参数选择插件
├── 协议匹配: 插件间协议发现与路由
├── 格式匹配: 文件格式 → 加载器路由
├── 依赖管理: 协议版本兼容性检查
├── 生命周期: 安装 → 加载 → 启动 → 运行 → 停止 → 卸载
├── 可撤销副作用: 卸载时完全清理
├── Git 集成: 所有操作自动 commit
├── 热插拔: 运行时安装/卸载/替换
└── 跨节点路由: 集群内插件发现与路由
```

5.2 插件定义格式

```yaml
# plugins/loader-apk/plugin.yml
plugin:
  id: "loader-apk"
  name: "APK 应用加载器"
  version: "1.0.0"
  description: "Android APK 应用加载器"
  
  type: "loader"
  
  git:
    repo: "https://hwrun.org/plugins/loader-apk.git"
    branch: "main"
  
  provides:
    - protocol: "LOADER-APK"
      version: "1.0"
  
  requires:
    - protocol: "PMP"
    - protocol: "FSP"
    - protocol: "NP"
    - protocol: "SP"
  
  formats:
    - name: "APK"
      magic: ["50 4b 03 04"]
      extensions: [".apk", ".aab"]
  
  params:
    - key: "apk.data_dir"
      type: "string"
      default: "/var/lib/hwrun/apk"
    - key: "apk.sandbox"
      type: "bool"
      default: true
    - key: "apk.max_memory"
      type: "string"
      default: "1GB"
  
  files:
    - "/usr/lib/hwrun/plugins/loader-apk.so"
  
  size: "2MB"
  
  license: "MIT"
  
  author: "HWRun Team"
```

```
插件状态机:

[未安装] → [已安装] → [已加载] → [运行中]
              │           │          │
              │           ├──────────┤
              │           │          │
              ▼           ▼          ▼
           [可切换]   [可暂停]   [可替换]
              │           │          │
              └───────────┴──────────┘
                      │
                      ▼
                 [已卸载/清理]
```

5.4 插件替换流程

```
替换流程 (运行时):

1. 用户修改参数:
   hwrun params set kernel.type freebsd

2. 组件总线:
   ├── 检测参数变化: kernel.type → freebsd
   ├── 查找对应插件: freebsd-kernel
   ├── 检查协议兼容性: 是否实现 HAP
   ├── git-storage 自动 commit: "切换内核: linux → freebsd"
   ├── 通知所有使用 HAP 的插件: "协议将切换"
   ├── 卸载 linux-kernel (保留状态)
   ├── 加载 freebsd-kernel
   ├── 注册 freebsd-kernel 到 HAP 协议路由
   └── 通知所有插件: "协议已切换"

3. 完成: 用户无感知，系统现在运行在 FreeBSD 内核上
```

七、标准化协议层

7.1 协议定义

```
HWRun OS 标准化协议

协议层 1: 硬件抽象协议 (HAP)
├── 定义: CPU/内存/存储/网络/GPU 的标准接口
├── 实现: 各硬件厂商提供驱动插件
└── 关键接口: cpu_info, mem_alloc, pcie_scan, irq_handle

协议层 2: 文件系统协议 (FSP)
├── 定义: 文件/目录/权限/挂载的标准接口
├── 实现: ext4 / btrfs / zfs 插件
└── 关键接口: open, close, read, write, stat, mkdir

协议层 3: 进程管理协议 (PMP)
├── 定义: 进程/线程/调度的标准接口
├── 实现: cfs / hwrun-sched 插件
└── 关键接口: fork, exec, wait, signal, scheduler

协议层 4: 网络协议 (NP)
├── 定义: socket/连接/数据包的标准接口
├── 实现: tcpip / zerotier 插件
└── 关键接口: socket, connect, send, recv, bind

协议层 5: 安全协议 (SP)
├── 定义: 认证/授权/加密的标准接口
├── 实现: apparmor / selinux 插件
└── 关键接口: authenticate, authorize, encrypt, decrypt

协议层 6: 格式加载协议 (LOADER)
├── 定义: 可执行文件格式加载的标准接口
├── 实现: ELF / PE / Mach-O / APK / EXE / DMG 加载器插件
└── 关键接口: detect_format, load, run, unload

协议层 7: Git 协议 (GIT)
├── 定义: 版本控制的标准接口
├── 实现: git-storage / git-sync / git-log / git-version 插件
└── 关键接口: commit, push, pull, clone, tag, checkout, log, compact

协议层 8: 用户界面协议 (UI)
├── 定义: 界面显示/交互的标准接口
├── 实现: cli / tui / gui / web 插件
└── 关键接口: render, input, event

协议层 9: 插件间通信协议 (ICP)
├── 定义: 插件之间收发消息的标准格式
├── 格式: Protocol Buffers
└── 关键接口: send, recv, reply, broadcast
```

十、Git 历史自动管理

10.1 设计原则

```
Git 历史自动管理策略

核心原则: 自动合并历史，保留有意义的差异
驱动方式: 时间 + 大小阈值
触发条件: Git 仓库大小 > 用户预设值
合并策略: 越近越细，越远越粗
Tag 保护: 有 tag 的提交永久保留
```

10.2 时间线合并粒度

```
时间轴: 过去 ←─────────────────────────────────────→ 现在

合并粒度曲线:

现在 ─────────────────────────────────────────────── 过去
   │                                                    │
   │  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐│
   │  │  小时  │  │  天   │  │  周   │  │  月   │  │  年   ││
   │  │  粒度  │  │  粒度  │  │  粒度  │  │  粒度  │  │  粒度  ││
   │  │ (细)  │  │       │  │       │  │       │  │ (粗)  ││
   │  └──────┘  └──────┘  └──────┘  └──────┘  └──────┘│
   │  最近 24h   7天内     30天内    90天内    更久    │
   │                                                    │
   └─────────────────────────────────────────────────────┘

粒度定义:
├── 小时粒度: 每个 commit 保留 (最细)
├── 天粒度: 合并成 1 天 1 个 commit
├── 周粒度: 合并成 1 周 1 个 commit
├── 月粒度: 合并成 1 月 1 个 commit
└── 年粒度: 合并成 1 年 1 个 commit (最粗)
```

10.3 Tag 保护规则

```
Git 历史保护规则

核心规则:
├── 有 tag 的 commit → 永久保留，永不合并
├── 系统版本 tag → 永久保留
├── 关键版本 tag → 永久保留
└── 用户自定义 tag → 永久保留

合并策略:
├── 只合并没有 tag 的 commit
├── tag 之间的 commit → 合并成 1 个 (保留前后的 tag)
└── tag 本身 → 不动

示例:
v1.0.0 (tag) ←→ (合并) ←→ v1.0.1 (tag) ←→ (合并) ←→ v1.1.0 (tag)
     │              │              │              │              │
     ▼              ▼              ▼              ▼              ▼
   永久保留      合并成1个      永久保留      合并成1个      永久保留
```

10.4 自动触发机制

```
触发条件:
├── 触发阈值: Git 仓库大小 > 用户预设值 (默认 1GB)
├── 检查周期: 每次 commit 后检查
└── 触发动作: 自动执行历史合并

用户预设值:
├── 默认: 1GB
├── 可调: hwrun params set git.history.max_size 2GB
└── 可调: hwrun params set git.history.max_size 500MB
```

10.5 合并算法

```
历史合并算法:

1. 检查当前 Git 仓库大小
2. 如果大小 > 预设阈值:
   ├── 按时间线分段
   │   ├── 最近 24h: 不合并 (保留所有 commit)
   │   ├── 7天内: 按天合并 (保留每天最后一个 commit)
   │   ├── 30天内: 按周合并 (保留每周最后一个 commit)
   │   ├── 90天内: 按月合并 (保留每月最后一个 commit)
   │   └── 更久: 按年合并 (保留每年最后一个 commit)
   │
   ├── 执行合并 (git rebase -i)
   │   └── 合并相邻 commit 成 1 个
   │
   └── 保留关键 commit (带有 tag 的永远不合并)
       └── 系统版本 tag 永久保留

3. 合并后检查:
   ├── 如果大小仍然 > 阈值 → 提高合并粒度 (周→月→年)
   └── 直到大小 < 阈值
```

10.6 合并粒度曲线

```
合并粒度曲线 (按时间距离)

粒度等级:
0: 不合并 (保留全部)
1: 按小时合并 (合并 1 小时内的 commit)
2: 按天合并 (合并 1 天内的 commit)
3: 按周合并 (合并 1 周内的 commit)
4: 按月合并 (合并 1 月内的 commit)
5: 按年合并 (合并 1 年内的 commit)
6: 全部合并 (只保留最新的 commit)

时间衰减公式:
粒度 = floor(log2(距离天数 + 1))

距离 0 天 → 粒度 0 (不合并)
距离 1 天 → 粒度 1 (小时)
距离 3 天 → 粒度 2 (天)
距离 7 天 → 粒度 3 (周)
距离 15 天 → 粒度 4 (月)
距离 31 天 → 粒度 5 (年)
距离 > 365 天 → 粒度 6 (全部合并)
```

10.7 用户配置

```yaml
# params/git.yml
git:
  history:
    max_size: "1GB"
    auto_compact: true
    
    granularity:
      - days: 1
        level: "hour"      # 1天内: 小时粒度
      - days: 7
        level: "day"       # 7天内: 天粒度
      - days: 30
        level: "week"      # 30天内: 周粒度
      - days: 90
        level: "month"     # 90天内: 月粒度
      - days: 365
        level: "year"      # 365天内: 年粒度
      - days: 0
        level: "all"       # >365天: 全部合并
    
    preserve:
      - "tags/*"           # 所有 tag 永久保留
      - "system-version-*" # 系统版本 tag
      - "kernel-upgrade-*" # 内核升级 tag
      - "security-*"       # 安全更新 tag
```

10.8 备份机制

```
详细历史备份:
├── 合并前: 将详细 commit 打包备份
├── 备份位置: /var/lib/hwrun/git-backup/
├── 保留策略: 最近 3 个月的备份
└── 用户可以手动恢复: hwrun git restore-history --date 2026-09-01
```

十一、可运行格式支持

11.1 设计理念

```
HWRun OS 可运行任何主流格式

支持的格式:
├── ELF (Linux)
```

11.2 加载器插件定义

```yaml
# plugins/loader-apk/plugin.yml
plugin:
  id: "loader-apk"
  name: "APK 应用加载器"
  version: "1.0.0"
  type: "loader"
  
  git:
    repo: "https://hwrun.org/plugins/loader-apk.git"
  
  provides:
    - protocol: "LOADER-APK"
  
  requires:
    - protocol: "PMP"
    - protocol: "FSP"
    - protocol: "NP"
    - protocol: "SP"
  
  formats:
    - name: "APK"
      magic: ["50 4b 03 04"]
      extensions: [".apk", ".aab"]
  
  params:
    - key: "apk.data_dir"
      default: "/var/lib/hwrun/apk"
    - key: "apk.sandbox"
      type: "bool"
      default: true
```

11.3 用户操作


十三、分布式原生

13.1 设计理念

```
HWRun OS = 一个操作系统运行在多个节点上

不是:
├── 节点 1: 运行 HWRun OS
├── 节点 2: 运行 HWRun OS
└── 集群管理工具管理这些独立 OS

而是:
└── HWRun OS (一个系统)
    ├── 节点 1: 系统的一部分
    ├── 节点 2: 系统的一部分
    └── 所有节点共同组成一个完整的操作系统
```

13.2 统一资源池

```
所有节点的资源组成统一的资源池。

用户提交任务，调度器自动选择最优节点。
用户不关心任务跑在哪台机器上。
```

13.3 节点加入 (Git 方式)

```yaml
# /etc/hwrun/cluster.yml
cluster:
  mode: "node"

    remote: "https://hwrun.org/system.git"
```

```bash
# 节点加入集群
hwrun cluster join https://hwrun.org/system.git

# 节点同步
hwrun cluster sync

```

二十四、总结

24.1 设计维度

维度 决策
项目性质 操作系统插件容器
设计哲学 一切皆插件，一切皆参数
版本控制 Git 原生，历史自动管理
微内核 ~5000 行 C，~200KB
插件粒度 超细粒度 (每个 .c 文件可独立)

24.2 最终定义

```
HWRun OS = 微内核 + 组件总线 + 参数系统 + Git + 协议定义 + 插件仓库

微内核:
├── 最小核心
├── 插件加载器
├── 组件总线接口
├── 参数系统接口
├── Git 接口
└── 协议路由表

组件总线:
├── 插件发现 (Git 仓库)
├── 参数匹配
├── 协议匹配
├── 格式匹配
├── 生命周期管理
├── Git 集成 (自动 commit)
├── 可撤销副作用
└── 热插拔

参数系统:
├── 所有配置是参数
├── 参数决定插件
├── 参数决定插件行为
├── 参数运行时修改
└── 修改自动生效 (git commit)

Git:
├── 系统本身是 Git 仓库
├── git-storage: 存储系统状态
├── git-sync: 集群同步
├── git-log: 审计日志
├── git-version: 版本管理
├── git-auth: 认证/权限
├── git-backup: 备份/恢复
├── git-compact: 历史自动管理
├── 所有操作自动 commit
├── Tag 提交永久保留
└── 历史自动合并压缩 (大小可控)

协议层:
├── 硬件抽象协议 (HAP)
├── 文件系统协议 (FSP)
├── 进程管理协议 (PMP)
├── 网络协议 (NP)
├── 安全协议 (SP)
├── 格式加载协议 (LOADER)
├── Git 协议 (GIT)
├── 用户界面协议 (UI)
└── 插件间通信协议 (ICP)

插件:
├── 所有功能都是插件
├── 内核 / libc / init / 文件系统 / 网络
├── Git 插件 (storage / sync / log / version / auth / backup / compact)
├── 格式加载器 (ELF / PE / Mach-O / APK / EXE / DMG / WASM / JAR)
├── 可独立安装/卸载/替换
├── 运行时热插拔
├── 参数驱动行为
└── 用户自己写插件

软件格式:
├── 没有专有格式
├── 只有 plugin.yml + 协议实现
├── 安装 = 安装插件 (git clone)
└── 运行 = 调用协议

异构集群:
├── 每个节点不同插件组合
├── 通过相同协议通信
├── 统一集群管理 (Git 同步)
└── 用户看到单一系统

Git 历史管理:
├── 触发条件: Git 大小 > 用户预设值 (默认 1GB)
├── 合并策略: 按时间线自动调整粒度
├── 粒度曲线: 越近越细，越远越粗
├── Tag 保护: 有 tag 的提交永久保留
└── 备份机制: 详细历史打包备份可恢复
```

24.3 一句话总结

HWRun OS = 微内核 + 组件总线 + 参数系统 + Git。插件提供能力，参数决定行为，Git 管理一切。改变参数就改变系统，替换插件就替换能力，所有操作自动 commit，可回滚到任意历史状态。Git 历史自动管理，大小永远可控，Tag 提交永久保留。所有功能都是插件，所有配置都是参数，所有历史都是 Git。软件没有专有格式，只有协议和插件。同一个系统可以运行 ELF、EXE、APK、DMG、WASM、JAR。集群内不同节点可以运行不同的插件组合，只要实现相同的标准化协议，就能组成一个统一的集群。系统本身就是 Git 仓库，一切操作都是 Git 操作。
