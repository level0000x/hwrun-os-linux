HWRun OS DRIVER 实现文档

模块名称： DRIVER (Device Driver Framework Protocol)
版本： 1.0.0
状态： 设计冻结
定位： 设备驱动框架协议，提供对硬件设备驱动的加载、卸载、枚举、控制、热插拔等功能的统一抽象
实现语言： C（内核模块）
依赖： 微内核（任务、IPC、内存）、METAPROTO（协议注册）、PARAM（参数读取）、LOG（日志记录）、HAP（硬件抽象）、PMP（进程管理）
提供协议： DRIVER

一、设计哲学

1.1 核心定位

DRIVER 是 HWRun OS 的设备驱动管理核心——所有与硬件设备驱动加载、卸载、枚举、控制、热插拔相关的操作都通过 DRIVER 协议进行。

```
DRIVER = 设备驱动框架协议 = 所有设备驱动操作的统一入口

上层插件 (HAP, PMP, NP, DISPLAY, STORAGE, INPUT, ...)
    │
    │  通过 DRIVER 协议加载/控制设备驱动
    ▼
DRIVER 插件 (内核模块)
    │
    │  基于 Linux 设备驱动模型
    │  ├── 设备模型 (Device Model)          → bus/device/driver 统一管理
    │  ├── Platform 框架                     → SoC 内部设备
    │  ├── PCI 子系统                        → PCI/PCIe 设备
    │  ├── USB 子系统                        → USB 设备
    │  ├── I2C/SPI 子系统                   → 低速总线设备
    │  └── 热插拔机制 (uevent)              → 设备动态发现
    │
    ▼
Linux 内核 (设备驱动模型 / sysfs)
```

1.2 设计原则

1. 协议驱动：所有设备驱动操作通过 DRIVER 协议进行
2. 统一模型：基于 Linux 内核的 Bus-Device-Driver 模型
3. 分离思想：驱动与设备分离，驱动只管驱动逻辑，设备只管硬件资源
4. 分层思想：同类设备提炼核心层，驱动只需“填空”
5. 热插拔支持：支持设备的动态发现和移除
6. sysfs 暴露：通过 /sys 文件系统暴露设备拓扑

1.3 驱动框架的层次结构

Linux 内核中的驱动框架可以从两个层面理解：

层次 说明
广义（驱动架构） Linux 驱动的整体架构与模型，即设备模型（Device Model）
狭义（驱动框架） 内核中用于组织和管理设备驱动的具体框架/子系统

Linux 驱动并不是“随便写个函数”，而是基于一套统一模型：

```
用户空间程序
    │
    │  系统调用
    ▼
内核 (进程调度 / 内存 / 文件系统)
    │
    │
    ▼
驱动框架 (bus / class / driver)          ← DRIVER 插件管理这一层
    │
    │
    ▼
具体硬件 (CPU 外设 / PCI / USB / I2C ...)
```

1.4 DRIVER 插件的本质

DRIVER 插件 = Linux 内核设备驱动模型的 HWRun 协议封装

Linux 内核的驱动模型建立在三个核心概念之上：

概念 说明 内核结构体
Bus（总线） CPU 和设备之间的通道，负责匹配设备和驱动 struct bus_type
Device（设备） 具体的硬件设备，描述硬件资源 struct device
Driver（驱动） 控制设备的软件逻辑 struct device_driver

三者的关系：

· bus 下面可以有许多 device，一个 device 必须属于一个 bus
· 每个 device 由一个 driver 驱动
· driver 需要和 device 匹配（通过名字、ID、compatible 等信息）

```
bus
├── device 1 ←── driver A (匹配)
├── device 2 ←── driver B (匹配)
└── device 3 ←── driver A (匹配)

内核负责：设备与驱动匹配、自动加载、电源管理、热插拔（uevent）[reference:19]
```

2.2 DRIVER 在 HWRun OS 中的位置

```
系统启动顺序：
BIOS/UEFI → 引导加载器 → 微内核 → METAPROTO → BUS → PARAM → LOG → GIT → HAP → PMP → FSP → NP → SP → LOADER → CLUSTER → INSTANCE → SANDBOX → INPUT → DISPLAY → PERMISSION → STORAGE → NODE_DISCOVERY → CONSENSUS → DRIVER → 其他插件
                                                                                                                                    ↑
                                                                                                                          DRIVER 在这里加载
```

DRIVER 插件在 CONSENSUS 之后加载，为系统提供设备驱动管理能力。

2.3 DRIVER 的上层消费者

上层插件 需要 DRIVER 提供什么
HAP (硬件抽象) 获取设备信息、加载硬件驱动
NP (网络协议) 加载网卡驱动
DISPLAY (显示) 加载显示驱动 (DRM/KMS)
STORAGE (存储) 加载存储设备驱动
INPUT (输入) 加载输入设备驱动
HOTPLUG (热插拔) 设备热插拔事件通知

```c
   驱动信息

    uint32_t flags;                 // 资源类型 (IORESOURCE_MEM, IORESOURCE_IRQ, etc.)

   Platform 设备 (对应 struct platform_device)
   ============================================================ */
typedef struct platform_device {
    char name[64];                  // 设备名称

    uint32_t num_resources;         // 资源数量

   Platform 驱动 (对应 struct platform_driver)

typedef struct platform_driver {

/* ============================================================
   DRIVER 上下文
   ============================================================ */
typedef struct driver_context {
    int initialized;
    uint64_t driver_task_id;        // DRIVER 自身的任务 ID

    platform_driver_t *platform_drivers;   // Platform 驱动列表

} driver_context_t;
```

```c
#include "driver_platform.h"

#include "driver_usb.h"
#include "driver_hotplug.h"

MODULE_LICENSE("GPL");
MODULE_AUTHOR("HWRun OS");
MODULE_DESCRIPTION("HWRun OS Device Driver Framework Protocol Plugin");
MODULE_VERSION("1.0.0");

static driver_context_t g_driver_ctx = {0};

/* ============================================================
   模块加载入口
   ============================================================ */
static int __init driver_init(void) {
    int ret;
    
    printk(KERN_INFO "HWRun DRIVER: Initializing...\n");
    
    // 1. 初始化上下文
    memset(&g_driver_ctx, 0, sizeof(driver_context_t));
    
    // 2. 初始化设备模型封装
    ret = driver_model_init();
    if (ret < 0) {
        printk(KERN_WARNING "HWRun DRIVER: Device model init warning\n");
    }
    
    // 3. 扫描现有设备
    driver_scan_devices();
    
    // 4. 注册 IPC 消息处理器
    ret = driver_ipc_register();
    if (ret < 0) {
        printk(KERN_ERR "HWRun DRIVER: Failed to register IPC handler\n");
        return ret;
    }
    
    // 5. 注册 DRIVER 协议（通过 METAPROTO - 通过 IPC）
    driver_register_protocol();
    
    g_driver_ctx.initialized = 1;
    printk(KERN_INFO "HWRun DRIVER: Initialized successfully\n");
    printk(KERN_INFO "  Device driver framework ready\n");
    
    return 0;
}

/* ============================================================
   模块卸载入口
   ============================================================ */
static void __exit driver_exit(void) {
    printk(KERN_INFO "HWRun DRIVER: Exiting...\n");
    
    driver_ipc_unregister();
    driver_cleanup_drivers();
    driver_cleanup_devices();
    
    g_driver_ctx.initialized = 0;
    printk(KERN_INFO "HWRun DRIVER: Exited\n");
}

module_init(driver_init);
module_exit(driver_exit);
```

5.3 Platform 设备驱动框架

Platform 总线是 Linux 内核中的一种虚拟总线，用于管理 SoC 内部设备。

```
Platform 设备驱动模型中，分为设备、驱动、总线3个实体[reference:28]：
├── platform_device   → 描述硬件资源（寄存器地址、中断号等）
├── platform_driver   → 驱动逻辑（probe、remove 等）
└── platform_bus      → 负责将设备和驱动绑定[reference:29]
```

哪些设备使用 Platform 总线？几乎所有直接连接到 SoC 芯片的外设：

· GPIO 控制器
· UART 串口控制器
· RTC 实时时钟
· 看门狗
· ADC/DAC
· PWM 脉冲宽度调制器
· DMA 控制器

```c
// driver/src/driver_platform.c

#include <linux/kernel.h>
#include <linux/platform_device.h>
#include <linux/slab.h>
#include <linux/string.h>

#include "driver.h"
#include "driver_platform.h"

/* ============================================================
   注册 Platform 设备
   ============================================================ */
int driver_platform_device_register(platform_device_t *pdev) {
    struct platform_device *dev;
    int ret;
    
    // 创建设备资源
    struct resource *res = NULL;
    if (pdev->num_resources > 0) {
        res = kmalloc(pdev->num_resources * sizeof(struct resource), GFP_KERNEL);
        if (!res) {
            return -ENOMEM;
        }
        for (int i = 0; i < pdev->num_resources; i++) {
            res[i].start = pdev->resources[i].start;
            res[i].end = pdev->resources[i].end;
            res[i].flags = pdev->resources[i].flags;
            if (pdev->resources[i].name[0]) {
                res[i].name = pdev->resources[i].name;
            }
        }
    }
    
    // 注册 platform 设备
    // 实际使用 platform_device_register()
    // 或 platform_device_alloc() + platform_device_add()
    
    ret = platform_device_register_simple(pdev->name, pdev->id, res, pdev->num_resources);
    
    if (res) {
        kfree(res);
    }
    
    return ret;
}

/* ============================================================
   注册 Platform 驱动
   ============================================================ */
int driver_platform_driver_register(platform_driver_t *pdrv) {
    struct platform_driver drv = {0};
    int ret;
    
    drv.driver.name = pdrv->name;
    drv.probe = pdrv->probe;
    drv.remove = pdrv->remove;
    drv.suspend = pdrv->suspend;
    drv.resume = pdrv->resume;
    
    // 设置设备树匹配表 (of_match_table)[reference:31]
    // 驱动通过 of_match_table 声明支持的 compatible 列表
    // 注册时由内核按"最具体 → 最通用"的规则匹配节点[reference:32]
    
    ret = platform_driver_register(&drv);
    return ret;
}
```

5.4 PCI 设备驱动框架

PCI 子系统负责总线枚举、资源配置、设备发现。

```
PCI 驱动框架层次[reference:37]：
├── drivers/pci/       → PCI 核心层
│   ├── probe.c        → 总线枚举
│   ├── bus.c          → 总线管理
│   └── pci-driver.c   → 驱动管理
├── struct pci_dev     → PCI 设备描述[reference:38]
└── struct pci_driver  → PCI 驱动描述[reference:39]
```

PCI 设备枚举流程：

1. 系统上电或 PCIe 设备热插拔时触发枚举
2. PCI 通用代码扫描物理总线
3. 读取每个设备的配置空间
4. 获取 Vendor ID、Device ID、BAR 等关键信息
5. 将设备登记到系统中

```c

#include <linux/slab.h>
#include <linux/string.h>

   ============================================================ */
// 驱动通过 ID 表声明支持的设备[reference:44]

static const struct pci_device_id driver_pci_ids[] = {

    // 4. 读取配置空间获取 BAR 地址

    // 存储设备 ID、厂商 ID、基地址寄存器（BAR）、中断号等关键信息[reference:47]
    
    return 0;
}

/* ============================================================
   PCI 驱动结构
   ============================================================ */
static struct pci_driver driver_pci_drv = {
    .name = "driver_pci",
    .id_table = driver_pci_ids,
    .probe = driver_pci_probe,
    .remove = NULL,
};
```

5.7 IPC 消息处理

```c
// driver/src/driver_ipc.c

#include <linux/slab.h>
#include <linux/uaccess.h>

#include "driver.h"
#include "driver_ipc.h"
#include "driver_model.h"
#include "driver_platform.h"
#include "driver_pci.h"
#include "driver_usb.h"
#include "driver_hotplug.h"

/* ============================================================
   IPC 消息处理入口
   ============================================================ */
void driver_ipc_handler(uint64_t from_task, void *data, size_t len) {
    uint32_t msg_type = *(uint32_t *)data;
    
    switch (msg_type) {
        case DRIVER_MSG_LIST: {
            // 返回驱动列表
            driver_info_t *drivers;
            uint32_t count;
            driver_list_drivers(&drivers, &count);
            ipc_reply(from_task, drivers, count * sizeof(driver_info_t));
            break;
        }
        
        case DRIVER_MSG_LOAD: {
            driver_load_req_t *req = (driver_load_req_t *)data;
            int ret = driver_load_module(req->module, req->args);
            ipc_reply(from_task, &ret, sizeof(ret));
            break;
        }
        
        case DRIVER_MSG_UNLOAD: {
            driver_unload_req_t *req = (driver_unload_req_t *)data;
            int ret = driver_unload_module(req->module, req->force);
            ipc_reply(from_task, &ret, sizeof(ret));
            break;
        }
        
        case DRIVER_MSG_DEVICES: {
            driver_devices_req_t *req = (driver_devices_req_t *)data;
            driver_device_info_t *devices;
            uint32_t count;
            driver_list_devices(&devices, &count, req->bus_type);
            ipc_reply(from_task, devices, count * sizeof(driver_device_info_t));
            break;
        }
        
        case DRIVER_MSG_BIND: {
            driver_bind_req_t *req = (driver_bind_req_t *)data;
            int ret = driver_bind_device(req->device, req->driver);
            ipc_reply(from_task, &ret, sizeof(ret));
            break;
        }
        
        case DRIVER_MSG_SCAN: {
            int ret = driver_scan_devices();
            ipc_reply(from_task, &ret, sizeof(ret));
            break;
        }
        
        default:
            printk(KERN_WARNING "HWRun DRIVER: Unknown IPC message type: %u\n",
                   msg_type);
            break;
    }
}
```

六、驱动框架分类

Linux 内核将设备驱动分为多个框架/子系统，驱动只需“填空”即可：

框架 用途 用户空间接口
字符设备 串口、传感器、自定义硬件 /dev/xxx
块设备 硬盘、SD卡、SSD /dev/sdX
网络设备 网卡、WiFi ifconfig / ip
Input 键盘、鼠标、触摸 /dev/input/
I2C I2C 设备 /dev/i2c-*
SPI SPI 设备 /dev/spidev*
USB USB 设备 /dev/bus/usb/
GPIO 通用 IO /sys/class/gpio/
DRM 显示 /dev/dri/
ALSA 音频 /dev/snd/

这些框架的好处：

· 不用重复造轮子
· 驱动更统一
· 更易于维护

十、总结

维度 决策
定位 设备驱动框架协议，所有设备驱动操作的统一入口
实现方式 Linux 内核模块 (.ko)
代码量 ~1500-2000 行 C
提供协议 DRIVER (v1.0)
依赖 微内核 IPC + METAPROTO + PARAM + LOG + HAP + PMP
核心模型 Bus-Device-Driver 模型
关键框架 Platform、PCI、USB、I2C、SPI
热插拔 uevent netlink 机制

DRIVER 是 HWRun OS 中设备驱动管理的核心插件。它基于 Linux 内核的 Bus-Device-Driver 设备模型，通过 DRIVER 协议向上层插件提供设备驱动的加载、卸载、枚举、控制、热插拔等完整的管理功能。设备模型让设备、驱动与总线之间形成清晰的组织体系，并通过统一的方式出现在内核和 sysfs 下。上层插件（HAP、PMP、NP、DISPLAY、STORAGE、INPUT 等）通过 DRIVER 协议加载和管理设备驱动，不直接操作内核的驱动模型接口。
